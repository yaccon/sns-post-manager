# Ver.3.8：X投稿形式選択とスレッドのiPhone検証

## 変更点
- X通常投稿（無料、加重280以内）、Xスレッド（無料、2〜5本、各パート加重280以内）、X Premium長文（本文1本、長文上限25,000カウントの保守的判定）
- 目標：日本語100・120・140文字、または上限内自動調整。Premiumは300・800・1,500・3,000文字から選択
- `sns-post-manager-format-settings-v1`に形式・目標・スレッド本数を保存。アプリを開き直しても前回の選択を引き継ぐ
- 投稿先をThreadsに変えてもXの形式設定は維持。Threadsは従来どおり通常1本で生成する
- **今日の投稿はメイン画面の先頭。** スレッドの各パートを順番にコピーし、コピー成功時のみ「コピー済み」を保存
- 投稿予定14/28/42枠の数を変えず、スレッド本文は`threadParts`に保存。投稿済み状態は予定枠単位
- JSONバックアップはVer.6で既存投稿・過去履歴・参考投稿・形式設定をまとめて保存。古いVer.5以下は現在の形式設定を勝手に変更しない
- Xのカウントはtwitter-text v3参考の**概算**。公開直前にX公式の投稿画面で最終確認する
- 投稿操作は手動。X APIや追加課金、投稿の自動化はない

### iPhone確認項目
1. 上記ページを開き、最上部の「📌今日の投稿」が、長い設定項目より前にある。
2. 「今日のテスト投稿（通常1本・スレッド3本）を追加」。各パートのコピー、コピー済み表示、Xを開く、投稿済み切替を試す。コピー済みは投稿済みではない。
3. AI生成欄で「無料X：スレッド（2〜5本）」と3本、目標120文字を選ぶ。更新を押さずページ再読み込みしても選択が残る。
4. 「生成指示をコピー」を押し、コピーした文章にスレッド本数・文字数が含まれることを確認。
5. X Premium長文、通常投稿、Threadsを切り替え、表示と記憶を確認。
6. テスト版に追加した投稿のバックアップJSONに`formatSettings`と`threadParts`があることを確認。古い本番JSONをテスト版に復元する必要はない。

### 安全な通常版への反映
1. 現在のVer.3.7.1の通常版は反映前まで維持する。
2. GitHub Actionsで旧版安全テスト・参考投稿テスト・Ver.3.8テストが全件合格する。
3. ユーザーがiPhoneで上記テストを確認し、通常版の最新バックアップJSONをiPhoneの「ファイル」アプリに保存・確認した後、ユーザーが本番反映を明示許可する。
4. その後にPRをmainへマージする。投稿一覧、過去履歴、投稿済み状態は旧キーをそのまま再利用。
5. 更新後、通常版でVer.3.8表示・既存投稿件数・投稿済み状態・参考投稿・形式設定を最終確認。
6. 問題時はコードだけロールバックし、ブラウザストレージを消去しない。

## 引き継ぎ
- 既存形式設定がなければ無料X通常1本、日本語120文字が初期値。
- 新設定は選択を変更した時点で保存。Xへ戻した時も前回値を再利用。
- 既存投稿は`postFormat`や`threadParts`がなくても表示・コピー可能。
- Threadsは今回スレッド対応せず、従来の1本形式を維持。
