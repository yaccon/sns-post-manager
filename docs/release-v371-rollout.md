# SNS投稿管理 Ver.3.7.1：通常版への安全な反映手順

## 検証済み
- iPhone実機：参考投稿保存・分析用コピー・編集削除・参考ライブラリのバックアップ復元
- iPhone追加再テスト：**生成に反映/お気に入りON/OFF表示、カイ14本の選択参考本文表示、参考投稿だけ保存→削除→復元、すべてOK（2026-10-15）**
- Node/GitHub Actions：旧データ安全性、参考投稿コピー/選択/生成、専用復元・二重復元・異常JSON・保存失敗の回帰テスト

## 既存データの保護
- 既存投稿キー `sns-post-manager-v1` をそのまま使い、データを初期化しない。
- 既存履歴キー `sns-post-manager-history-v1` を維持し、X/Threads区別も維持する。
- 参考投稿は新しい保存領域 `sns-post-manager-references-v1` のみを追加する。
- Ver3.7.1本番は検証用ページ `qa-references-v371.html` のテストデータを自動インポートしない。
- POST一覧、過去履歴、参考投稿をversion 5 JSONにまとめてバックアップ・復元できる。旧version 4 JSONを読み込んでも参考投稿は消さない。
- 参考投稿専用バックアップは投稿予定/履歴を含まず、ライブラリ側の専用復元で読み込む。投稿全体の復元欄で誤って選んだ場合は専用欄への案内を表示する。

## 統合前の最終確認
1. 現在の通常版Ver3.6を開いて、**いまの最新状態**で「バックアップを保存」し、iPhone「ファイル」にJSONが存在することを確認する。Ver3.7.1のテスト用バックアップとは別物。
2. 可能なら投稿予定数・投稿済み数・履歴件数を控える。
3. Pull Requestの回帰テストが全て成功していることを確認する。
4. 上記を確認しユーザーが通常版への反映を明示的に許可してから、このPRをmainへマージする。

## 反映後
1. 通常URL `https://yaccon.github.io/sns-post-manager/` を開き、Ver3.7.1の表示を確認。
2. 旧投稿予定・履歴・投稿済みが残っていることを確認。
3. 参考投稿を1件保存し「生成に反映：ON」、14本生成欄の実際の参考本文表示を確認。
4. 参考投稿専用バックアップのファイル名・保存と復元を確認。
5. 不具合時は以前のコードへ戻す。端末のブラウザデータは消さない。必要なら手元のJSONから復元。

## 注意
- 参考投稿のURLだけでは外部SNSの本文は自動取得しない。
- 参考資料はChatGPTに渡すユーザーの明示的なコピー操作時にのみ生成指示へ含まれる。自動投稿や自動分析はしない。
- 文章の転載・言い換えではなく、フック・構成・読者心理を抽象化して独自投稿を生成する設計。
- 無料配布向けのアカウント編集、操作説明、各種環境検証は別工程。
